<Aside type="tip" title="Mobile: auto-collapse (task 2640)">
Breadcrumbs are a **desktop pattern**; on a phone-narrow container the trail
**auto-collapses to first + “…” + current** (see the Mobile stage above). Every hidden
ancestor stays reachable through the same keyboard-operable overflow menu, and the
current crumb keeps its ellipsis. The desktop render is untouched; if a mobile surface
can use back-navigation or a tree instead, prefer that.
</Aside>

```kotlin
// Android: Jetpack Compose. There is NO breadcrumb component: the app wayfinds
// with system/arrow back + an indented file tree (see FilesSheet.kt). The path's
// leaf is the filename; "up" is the back arrow. This is the platform-native
// equivalent of a trail, documented honestly, not a fabricated API.
import androidx.compose.material.icons.Icons
import com.nockerl.app.core.ui.NockerlIconButton

@Composable
private fun ViewerHeader(filePath: String, onBack: -> Unit) {
    val fileName = filePath.substringAfterLast('/')   // leaf of the path
    Row(verticalAlignment = Alignment.CenterVertically) {
        NockerlIconButton(
            icon = Icons.AutoMirrored.Filled.ArrowBack,   // "up" one level
            contentDescription = "Back to file tree",
            onClick = onBack,
        )
        Text(fileName, style = MaterialTheme.typography.titleMedium, maxLines = 1)
    }
}
```

</Fragment>

// macOS: SwiftUI. There is NO breadcrumb component in Nockerl Voice: hierarchy

NavigationStack {

        .navigationDestination(for: FileNode.self) { node in

}

<Aside type="caution" title="Cross-platform drift (tracked for reconciliation)">
Breadcrumbs are a **web-only** pattern today. The shipped natives wayfind differently,
which is correct for those surfaces:

- **No native component.** Android (`FilesSheet`) and Voice (`SettingsView`) use **back
  navigation + indented trees**, not a horizontal trail. The TypeScript API is the
  canonical one; the Kotlin/Swift columns document the real stand-in.
- **Shared vocabulary, not a port.** The web trail deliberately reuses house parts: the
  **chrome surface + 1.5dp cyan signature line** (the apps' header treatment), the **house
  chevron** as the separator, and the **root/folder/task/file** leading glyphs. It reads
  as Nockerl without inventing anything mobile doesn't have.
</Aside>
