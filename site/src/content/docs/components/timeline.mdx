`TimelineEvent` fields: `status` is `'success' | 'warning' | 'error' | 'info' | 'neutral' | 'accent'`
(warm status + the cyan `accent` for the one highlight / live event). `time` is the relative
gutter label (`"2m"`); `datetime` is the absolute ISO for the `<time>` element. `live` pulses the
node; `mono` renders a tool-call title; `hollow` is a quieter routine node; `meta` is an inline chip.

<Aside type="caution" title="Cross-platform drift (tracked for reconciliation)">
Timeline is the **chronological event feed** (each node is a *moment in time*: timestamp +
what happened), distinct from the [Stepper](/components/stepper/) (a *forward process* with
done/current/upcoming flow state) and the [List](/components/list/) (plain rows). These are the
real divergences:

- **No platform ships a dedicated timeline yet.** The look + API are designed from the shipped
  event-sequence surfaces: Android's `AgentTranscriptPanel` + `AgentTranscriptSegments` (a
  time-ordered run of `session_init` / `tool_use` / `done` / `error` events) and `NotificationRow`
  (`formatTimeAgo`); Swift's `HistorySection` (a reverse-chronological timestamped list). The
  `NockerlTimeline` symbols above are the **intended** components to extract.
- **Relative time:** the demo uses Android's `formatTimeAgo` ramp (`just now · 2m · 1h · 3d · 1w ·
  1mo`); Swift's `HistorySection` renders an absolute `month().day().hour().minute()` instead. One
  format (relative gutter + absolute `<time>` tooltip) should win.
- **Two-sided + load-earlier:** web-original here; the apps' feeds are single-sided and paginate via
  scroll. Track before adopting on Android/Swift.
</Aside>
