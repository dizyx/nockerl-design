```swift
// macOS SwiftUI. The ROW ships as `NockerlNavRow`, built to the NockerlNavItem canon.
// The sidebar SHELL stays app-side (a translucent panel reading the app's router) until
// a Swift nav-surface ships. Voice's hand-rolled SidebarRow has been retired.
//
// Scope: this sidebar belongs to one window, not to the app. Voice is menu-bar-first, so
// closing the window leaves a native status-item menu as the always-on navigation. That
// menu is a macOS affordance the framework deliberately does not model.
import NockerlDesign

// Width is a token, never a literal. `containerXs` resolves to 216pt.
private let sidebarWidth: CGFloat = NockerlSize.containerXs

// The palette resolves per color scheme rather than reading a global.
private var palette: NockerlPalette { NockerlPalette.resolve(effectiveScheme) }

private var sidebar: some View {
    VStack(alignment: .leading, spacing: 3) {
        // The brand slot is the packaged lockup at its default mark height, never the
        // mark plus a separate text run.
        HStack(spacing: 0) {
            NockerlLockup(product: "Voice")
            Spacer(minLength: 0)
        }
        .padding(.horizontal, 16)
        // macOS only: the window hides its title bar, so the brand clears the traffic
        // lights that float over the top-left corner. The web inherits none of this.
        .padding(.top, 50)
        .padding(.bottom, 16)

        ForEach(AppSection.navItems) { section in
            NockerlNavRow(section.title, selected: router.section == section) {
                router.section = section
            } icon: {
                Image(systemName: section.icon)
            }
            .padding(.horizontal, NockerlSpace.space2)  // padding rides the row, not the stack
        }
        Spacer(minLength: 0)
        // Settings is a peer destination held out of the main list and pinned, not a
        // separate footer vocabulary: same row component, same selected treatment.
        NockerlNavRow(AppSection.settings.title, selected: router.section == .settings) {
            router.section = .settings
        } icon: { Image(systemName: AppSection.settings.icon) }
            .padding(.horizontal, NockerlSpace.space2)
            .padding(.bottom, 14)
    }
    .frame(width: sidebarWidth, alignment: .leading)
    .background(palette.canvas.opacity(0.3))            // translucent: the facet field reads through
    .overlay(alignment: .trailing) { Rectangle().fill(palette.cardHairline).frame(width: 1) }
}
```

**Why the panel is translucent.** One background owns the whole window, and the sidebar is
a translucent plane floating on top of it rather than an opaque panel with its own fill.
That is the transferable principle. Voice keeps the tint at `canvas` opacity `0.3` and
deliberately declined the heavier `surface.translucency.sidebar` token, which would thicken
the veil until the faceted field stopped reading through. The hidden title bar and the
traffic-light clearance above are macOS-only staging for that same effect.

The ROW ships as `NockerlNavRow`. The sidebar SHELL stays app-side (a translucent panel
reading the app's router).

**The state ladder.** `NockerlNavRow` carries **no wash on any state**, which is the
ratified "state by outline, not fill" position:

- **Rest:** `onChromeMuted` ink at **light** weight, no border.
- **Hover** (unselected only): the ink raises to `onChrome` and a **neutral gray `divider`
  hairline** border appears. Never cyan, because cyan is reserved for selection.
- **Selected:** a thin `accentPrimary` border at **45%**, accent ink, and a **medium**
  label weight. The leading icon stays, and there is no left rail and no stripe.

Weight is a selection signal here, so the resting weight is light and only the selected row
steps up. It steps up to medium and no further: the type ramp caps at 500, so `semibold` is
out of bounds.

Row metrics are the canon's: min-height 40, padding 12/8/8, radius `control`. Press feedback
is a 0.985 scale, a transform rather than a fill change.

<Aside type="caution" title="Cross-platform drift">
The **sidebar** is the persistent, in-layout nav column, the **`inline` role of the ONE
nav-surface**: `NockerlNavSurface` (= `NockerlDrawer`) is a single edge-anchored surface with
`mode: inline | overlay`. `inline` is this persistent rail; `overlay` is the
[drawer](/components/drawer/) (a scrim panel that opens / closes). [App shell](/components/app-shell/)
composes ONE nav-surface, not two. The sidebar never floats over content and never dims it. Its
rail chrome (grouped sections, collapse-to-rail, footer) is the reference `inline` nav content,
and the shell-level convergence lands with App shell.

Platforms are allowed to diverge while the migration runs. What follows is the honest state
today, not a defect list.

- **Selection reads by outline on every platform.** Accent border, accent ink, and the
  leading icon, with **no wash**, no left rail, and no stripe (law §6). The Swift row
  already carries no wash. The web is being conformed to the same position, so the soft
  cyan wash it previously used comes out; the law does not move.
- **Hover on an already-selected row differs on purpose.** Swift answers nothing: on macOS a
  selected sidebar row is inert under the pointer, Voice ships that, and it is approved. The
  web brightens the row's existing cyan edge to full strength instead, because a pointer-first
  surface that answers nothing on hover reads as disabled. It reuses the channel selection
  already owns rather than adding a wash, so law §6 still holds, and a border colour is
  interpolatable, so law §7 does too. This is the platform behaviour honoured per law §9, not
  drift: the learning transfers, the macOS habit does not.
- **Android has no side rail.** Voice and web use a vertical sidebar; Android's persistent
  nav is **top chrome** (project + session rows that collapse *up* under the title bar).
  A `NavigationRail` / `PermanentNavigationDrawer` is not used today.
- **Collapse:** web collapses to an **icon-only rail** (with tooltips). The Swift panel is
  a fixed `containerXs` width with no rail, and Android collapses the chrome **upward**,
  not sideways. Collapse is framework-original and has not shipped on Swift.
- **Grouped sections, sub-items, counts, and the profile footer are framework-original.**
  None has shipped on Swift, whose sidebar is a flat list of five destinations. They are
  kept here as the reference web pattern, not reported as harvested from a shipping app.
- **Scope differs.** The Swift sidebar belongs to one window, not to the app: Voice is
  menu-bar-first, and a native status-item menu remains after the window closes. That menu
  is a macOS affordance the framework does not model, and the web has no equivalent.
- **Keyboard support does not transfer.** The Swift rows leave the focus chain and have no
  arrow-key traversal, which is defensible on macOS and prohibited on the web. See the
  Swift `focus` row above.
</Aside>
