// Android: Jetpack Compose. No NockerlCallout ships yet; this is the proposed
// com.nockerl.app.core.ui.NockerlCallout. It is a RECESSED content aside (a
// tonal wash over canvasAlt + a tone hairline + a FILLED tone icon disc at the

There is no `dismissible` / `onDismiss` / `action`. A callout is **persistent**
editorial content. For a dismissible, action-bearing, app-state alert, use the
[Banner](/components/banner/).

<Fragment slot="kotlin">

`NockerlCallout` is the proposed Compose component: a recessed `Box` (panel
radius) with a tonal wash over `canvasAlt`, a tone hairline, an inner top shadow
(the recessed-well depth), and a **filled leading tone disc** (nested hairline
frames for the `important` tone), never a left rail (Law 6). It is deliberately
**not** a `NockerlSurface`/`NockerlCard` (those lift); a callout sinks into the
page like body content. The body is markdown via the shared `MarkdownBody`.

<DocCallout tone="warning" title="Cross-platform drift (tracked for reconciliation)">
The callout now **ships on web** as `NockerlCallout` in `@dizyx/nockerl-react`, and on both
natives as `NockerlCallout`. The web component is the one documented above; the native
surfaces are on their own migration track, so treat the sections below as the reconciliation
list rather than as a description of one shared API. The callout stays deliberately
**distinct from the
[Banner](/components/banner/)**: a banner is a *lifted, transient inline alert*
(drop shadow + catch-light + status wash + an X + an action, reacting to app
state); a callout is a *recessed, persistent editorial aside* (an inset tonal well
+ a filled tone disc + prose, part of the document flow, no dismiss). The
divergences to reconcile when it lands, tracked in the [Review queue](/review-queue/):

- **Source patterns differ:** Android has the inline `ThinkingSegment` (italic + muted
  prose) and the `ToolSegment` (a tonal inset + hairline), but neither is a reusable aside.
  Voice has the `SettingsCard` eyebrow + the `InfoTip` popover, but no in-content note.
  This page proposes the shared one.
- **`important` tone color:** this is the **one** place cyan is used editorially (brand
  emphasis, not status). The warm tones map to status tokens; one cyan-vs-status mapping
  should be canonized so callout and banner stay legibly different.
- **Quote treatment:** the `quote` tone reuses Android's italic + muted reasoning style;
  Voice/web would need a matching italic prose style + a quote glyph token.
</DocCallout>
