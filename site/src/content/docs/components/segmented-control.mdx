```tsx
          { value: 'board', label: 'Board', icon: 'board' },

      />

  );
```

```kotlin
// Android (Jetpack Compose). PUBLISHED: com.dizyx.nockerl.design.components.NockerlSegmented
// (com.dizyx.nockerl.design on GitHub Packages Maven). One muted track; the ACTIVE
// segment still carries a cyan FILL here, where the ratified expression is the sliding
// OUTLINE (border + ink, see the drift note); the rest stay transparent + muted.
// Pass Modifier.fillMaxWidth() for a full-width control.
import com.dizyx.nockerl.design.components.NockerlSegmented

enum class TaskView(val display: String) { LIST("List"), GRID("Grid"), BOARD("Board") }

var view by remember { mutableStateOf(TaskView.LIST) }

NockerlSegmented(
    options = TaskView.entries.toList(),
    selected = view,
    onSelect = { view = it },
    label = { it.display },
    modifier = Modifier.fillMaxWidth(),
)
```

<Aside type="caution" title="Cross-platform drift (tracked for reconciliation)">
Segmented control is the **connected, single-track view/mode switch**, distinct
from its neighbours: [tabs](/components/tabs/) navigate **page/section content**
(each tab owns a tabpanel; `role="tablist"`), whereas a segmented control just
flips a small set of mutually-exclusive **views/modes** with no associated panels
(`role="radiogroup"`). A [radio group](/components/radio-group/) is the same
single-choice intent but **looser and labelled**: separate rows that can carry
descriptions; reach for it for 4+ rich choices, and for the segmented control for
**2 to 5 compact peers**.

Real divergences between the shipped platforms:

- **Active-segment treatment** *(ratified)*: the selected segment is the **sliding cyan
  outline**, accent border + accent ink with no wash, per design laws §6 and §7, which name
  the filled cyan pill as the former treatment. The Swift idiom on this page already draws
  that outline at the selection weight (`border.width.selection` @ `border.opacity.selection`);
  the published Compose control still fills its active segment, so Android is the platform
  that converges here.
- **The slide.** Settled alongside it: the marker **animates transform + width, never the
  fill**, wherever the control is ours. Compose already slides its indicator; the Swift idiom
  cuts straight to the new stroke and adopts the slide.
- **Track surface.** Swift uses the inset `canvasAlt` well (radius 10, 4pt
  inset); Compose uses `cardAlt2` at the control radius (2dp inset). Web sinks the
  track as a recessed well at the **12px control radius**, which is close, but the
  inset radius/value should converge on tokens.
</Aside>
